四、资料范围 scope：只根据这篇资料自身判断，不能从候选报道反推。
- single：核心报道只有一个具体发生，或围绕该发生的一项评测、分析、回应。同一补丁集在同一轮提交中的多个补丁，以及这次提交说明的影响、测试结果和合并计划属于 single。没有具体发生的单一观点或教程可以是 single，但 fact 为 null；不能用“讨论同一个议题”把多个发生合成 single。
- composite：正文实质性报道多个可以各自成条的发生、独立补丁集或不同人的发言。先数清主体各自做了什么，再判 scope：共同子系统、日期、大会、总公告或讨论议题都不能把它们变成一次发生。多位演讲者在同场会议分别讲话，是多个发生；总结其共同观点的会议评论仍是 composite，不得创造“多位维护者共同发表一次演讲”的 fact。大会回顾与多个独立内核改动的总览同理。仅把其他改动/人物用作背景、比较或例证，正文仍集中于一个发生或一项方法，则不是 composite。
- 多条 CVE 的批量列表、多个互不相同版本事件的汇总通常是 composite；仅把其他版本或漏洞作为背景、比较或影响范围，正文仍集中于一个发生，则不是 composite。
- unknown：材料不足以辨认范围。不要仅凭标题词、篇幅或是否能抽到 fact 判断。

五、事实 fact：抽取本条资料当前报道的那次发生，供同事实归组使用：title（≤30 字），subject（做出动作的主体），action（本次动作），object（动作的具体对象），occurredAt（原文明示的本次动作发生日期 YYYY-MM-DD，未知为 null）。机构或维护者团队提交的内核改动以实际提交方为 subject，即使消息由个人账号宣布；个人演讲或观点本身以发言者为主体，不因其任职单位就声称机构发布。composite 必须为 null；没有可确认发生的观点稿也可为 null。
先分清当前动作与背景：
- X 主帖新增了基准结果、回归修复、回应或合并消息时，fact 必须是主帖的这次动作；引用的旧补丁帖只说明被测试/回应的对象，不能代替主帖事实。例：测试机构主帖公布内核基准结果并引用维护者的补丁公告，主体是测试机构，动作是公布基准结果，对象是该内核改动的测试结果，不是维护者再次提交补丁。
- 主帖仅转述或引介引用帖、自己没有另一项动作时，可以抽取引用中被转述的同一次发生；不要把一次转发本身虚构成补丁的新提交或新合并。
- 新写的介绍、教程、复盘、技术解读涉及既有改动时，抽取这次介绍/教程/解读及其明确新增内容，不能因正文回顾了提交或合并而仍写“提交/合并/发布”。例：“上周合并了补丁，今天介绍其中机制”是介绍机制；上周只属于背景合并，不能填作本次介绍的 occurredAt。若正文明确表示该机制本次才合入主线，则按这次合并抽取。
- 发布时间、抓取时间、被引用帖的时间不能补作当前动作的日期。“今天”可结合本条原文发布时间解析；只有背景日期或没有明确日期时保持 null。
- 长期维护的内核版本页、补丁状态页、硬件支持表和基准说明页，仅列出既有版本、提交日期、支持状态或成绩，不等于本次发布内核、合并补丁或公布新评测。没有原文明示的新动作时，scope 为 unknown、fact 为 null；不能把“页面收录了”改写成“维护者新发布了”。
- CVE 公告的当前事实是披露、修复或更新影响范围，不把“受影响”写成“已利用”。只有原文明示在野利用、攻击活动或等价证据时，action/object 才能声称已利用。版本公告区分 mainline、RC、stable/LTS；合并窗口的提议、拉取请求与完成结果不能混写。
fact 非 null 时还包含 evidence 和 conditions：evidence 只复制支持核心事实的一句原文（≤600 字符，找不到为 null）；conditions 是最多 4 条决定结论适用范围的原文短句，每条只有 {"quote":"原文的一句连续短句（≤400字符）"}。本步骤不翻译、不概括条件，只摘录。
evidence 必须支持上面选定的当前动作。主帖有新动作时从主帖摘取，不拿引用中的旧发布句子证明本次评测；只有主帖纯转述引用时才用引用帖的核心证据。
通读全文（包括文末的测试环境、内核配置和支持范围）后，条件优先级为：1. 结论成立所需的内核版本、配置、硬件与工作负载，以及不适用的例外，二者必须同时保留并指明各自对象；2. 受影响的架构、设备、发行版与版本范围；3. 仍在 RFC、测试或未来才合并的限制。不要用一般性能宣传、无方法的榜单成绩或普通使用场景占用条件名额。没有明确条件才给 []，不把提案写成已合并。
安全条目的 conditions 还应优先保留受影响版本、修复版本、LTS 状态、利用前提和支持期限；某发行版或单一 stable 分支已修复，不代表全部上游与下游分支已修复。
每个 quote 只承载一句原文；不同位置的条件分别成项，不能串成一个段落。例：原文有 “The regression affects arm64.” 和 “x86 is unaffected.”，应输出 [{"quote":"The regression affects arm64."},{"quote":"x86 is unaffected."}]，不能写成 “The regression affects arm64... x86 is unaffected.”。保持原文语言和字符；超过长度就选较短的完整句子。不要翻译、改写、省略中间文字或自行加入 ... / …；拼接的引文会被丢弃。quote 必须是收到的原文正文/帖子里能连续查到的文字，不来自标题、来源标签或中文译文。

输出前核对当前动作（优先于标题和宣传措辞）：标题里的 Introducing、介绍、重大更新不能覆盖正文明确的先后关系。正文若说此前已经合并、现在分享其中机制或讲解用法，本次 action 和 fact.title 必须写介绍/讲解；只有正文明确该改动本次才合入主线，才写合并。evidence 摘取当前分享/讲解的句子，不能摘背景合并句来证明新合并。没有明示本次介绍发生在哪一天，occurredAt 必须为 null，不从文章发布时间或此前提交日期补齐。
标题里的 “critical”“release”“fixed” 同样不能覆盖正文明确的范围与阶段；提议不是已合并，概念验证不是在野利用，受影响不是已利用。
